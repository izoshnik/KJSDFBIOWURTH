# TG Broadcast — рассылка из «Избранного» Telegram

Настольная программа для Windows 10/11. Она замечает новое сообщение в вашем «Избранном» (Saved Messages), показывает его предпросмотр и после вашего подтверждения копирует сообщение в выбранные чаты. Сообщение копируется без подписи «Переслано от», с сохранением форматирования, фото, подписей и альбомов.

> Программа рассчитана на ваши собственные сообщения и чаты, которые вы выбрали сами. Она не предназначена для спама и не пытается обходить ограничения Telegram.

## Быстрый старт (Windows)

1. Установите **Python 3.11–3.13** (рекомендуется 3.12) с [python.org](https://www.python.org/downloads/) и отметьте галочку «Add python.exe to PATH».
2. Получите **API ID** и **API Hash**: откройте https://my.telegram.org, затем **API development tools** и создайте приложение (название может быть любым).
3. Дважды щёлкните `run.bat`. При первом запуске он создаст окружение `.venv` и установит зависимости.
   Если запуск прервался с ошибкой, удалите папку `.venv` и запустите `run.bat` снова.
4. В программе введите API ID и API Hash, затем номер телефона, код из Telegram и, если он включён, пароль двухэтапной аутентификации.
5. На вкладке **«Чаты»** отметьте получателей.
6. Отправьте сообщение в «Избранное». Появится окно подтверждения, в котором нужно нажать **«Начать рассылку»**.

### Сборка EXE

Запустите `build_exe.bat`. Он установит зависимости, прогонит тесты и соберёт `dist\TgBroadcast.exe` (PyInstaller, один файл, без консоли).

### Запуск вручную (любая ОС)

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt     # Linux/macOS: .venv/bin/pip
.venv\Scripts\python main.py
```

## Вкладки

| Вкладка | Что там |
|---|---|
| **Главная** | Статус подключения, последнее сообщение из «Избранного», кнопка «Разослать это сообщение…» |
| **Чаты** | Все диалоги, поиск, чекбоксы, «Выбрать все», «Снять выделение», исключение чатов. Выбор сохраняется. Чаты без права отправки (чужие каналы, группы с запретом) скрыты и не могут стать получателями |
| **Рассылки** | Задания, прогресс, счётчики «Успешно / Ошибка / Ожидают отправки / Результат неизвестен», кнопки «Пауза», «Продолжить», «Отменить оставшиеся отправки», «Повторить ошибочные», «Проверить «неизвестные»», «Разрешить повтор «неизвестных»…», «Запустить повторно…» |
| **История** | Результат по каждому чату, фильтр, журнал переходов состояний (двойной щелчок) |
| **Настройки** | API ID/Hash, вход, **выход из аккаунта**, интервал между отправками, предел FloodWait, диагностика, открытие журнала и папки данных |

## Как устроена защита от дублей

**Ключи.** Ключ источника: `аккаунт:исходный_чат:id_сообщений`. Ключ задания (`job_key`): ключ источника плюс `#runN`. Ключ отправки (`delivery_key`): ключ задания плюс `->целевой_чат`. Все три ключа уникальны в SQLite (`UNIQUE`).

**Двойное нажатие, повторное событие Telegram, перезапуск.** Второе задание для того же сообщения не создаётся. Повторное событие о том же сообщении игнорируется (таблица `detected_messages`). Повторный запуск уже выполненной рассылки возможен только после отдельного подтверждения.

**Резервирование до сети.** Каждая отправка атомарно переводится из «ожидает» в «отправляется» (`BEGIN IMMEDIATE` и `UPDATE … WHERE state='pending'`) и фиксируется на диске (`synchronous=FULL`) ещё до запроса к Telegram. В той же транзакции проверяется, что это сообщение не отправлялось, не отправляется и не имеет неизвестного результата в этом чате в рамках другого задания.

**Одна рассылка за раз.** Внутри процесса это обеспечивает блокировка `asyncio.Lock` и атомарный переход задания в состояние «выполняется». Вторую копию программы с той же базой запустить нельзя: её не пускает файловая блокировка.

**`random_id`.** Идентификаторы `random_id` для запроса генерируются один раз и сохраняются в базе. Если вы вручную разрешите повтор, будут отправлены те же `random_id`, и Telegram сможет распознать дубликат (ошибка `RANDOM_ID_DUPLICATE` в этом случае считается успешной доставкой).

**Обрыв связи или сбой во время запроса.** Такая отправка получает статус **«Результат неизвестен»** и **никогда не повторяется автоматически**. После аварийного завершения или отключения питания все незавершённые отправки при следующем запуске помечаются как «неизвестные», а задания ставятся на паузу. Дальше можно:
- нажать **«Проверить «неизвестные»»**: программа ищет в целевом чате ваше сообщение, появившееся после начала попытки, и сравнивает текст и id медиа. Если оно найдено, отправка помечается успешной;
- нажать **«Разрешить повтор «неизвестных»…»**: это делается вручную, с предупреждением о возможном дубле.

**FloodWait / SlowMode.** Telegram не выполнил запрос, поэтому отправка возвращается в очередь и повторяется после указанного ожидания, не более 3 раз. Если ожидание больше настроенного предела, задание встаёт на паузу. `PEER_FLOOD` (ограничение аккаунта) и потеря авторизации сразу ставят задание на паузу.

**Однозначный отказ** (нет прав, медиа запрещены, вы заблокированы и т.п.): статус «Ошибка», сообщение точно не доставлено. Повтор выполняется только кнопкой.

**Отмена** затрагивает только ещё не начатые отправки.

### Честное ограничение

Telegram API не даёт подтверждаемой идемпотентности на неограниченное время. Если соединение оборвалось после того, как сервер принял запрос, но до получения ответа, клиент не может достоверно узнать результат. Поэтому программа **не обещает абсолютного отсутствия дублей**. Вместо этого она никогда не отправляет повторно без вашего решения, сохраняет `random_id` для повторов и даёт инструмент проверки.

## Отправка сообщений

- Используется `messages.forwardMessages` с флагом `drop_author` (то же, что «Переслать без автора» в официальных клиентах). Медиа не скачиваются и не загружаются заново, форматирование, ссылки и подписи сохраняются.
- Альбом отправляется одним запросом и остаётся альбомом. Сообщения альбома собираются из «Избранного» автоматически.
- Поддерживаются текст, фото, видео, документы, GIF, аудио, голосовые, стикеры, опросы, контакты и геопозиция.
- Не отправляются (окно подтверждения сразу показывает причину, кнопка запуска неактивна): сообщения с защитой от пересылки, самоуничтожающиеся медиа, live-геопозиция, неподдерживаемые типы.
- Если в чате запрещены медиа, отправка в него завершится ошибкой. Программа **не** отправляет туда молча один текст.
- «Избранное» никогда не попадает в список получателей.

## Данные и безопасность

Все данные хранятся в `%APPDATA%\TgBroadcast\` (в Linux/macOS — в `~/.tgbroadcast`, путь можно переопределить переменной `TGBROADCAST_HOME`):

| Файл | Назначение |
|---|---|
| `config.json` | API ID/Hash и параметры. В исходном коде ключей нет |
| `account.session` | Сессия Telegram. **Никому не передавайте этот файл:** он даёт полный доступ к аккаунту |
| `broadcast.sqlite3` | Чаты, задания, история |
| `tgbroadcast.log` | Журнал. Коды и пароли туда не пишутся, номера телефонов и хэши маскируются |

`.gitignore` исключает сессии, конфиг, базу и журналы из репозитория. Кнопка «Выйти из аккаунта» после подтверждения завершает сессию в Telegram и удаляет локальный файл сессии. История рассылок при этом сохраняется. Без вашего действия программа ничего не удаляет.

## Архитектура

```
main.py                       запуск, блокировка второго экземпляра, восстановление после сбоя
tgbroadcast/db.py             схема SQLite, ключи, атомарное резервирование, переходы состояний
tgbroadcast/engine.py         последовательная рассылка, пауза/отмена, FloodWait, «неизвестно»
tgbroadcast/telegram_service.py  Telethon: вход, диалоги и права, «Избранное», предпросмотр, отправка, проверка
tgbroadcast/ui.py             Tkinter-интерфейс; Telethon работает в отдельном потоке (окно не зависает)
tgbroadcast/infra.py          пути, config.json, журнал с маскированием, файловая блокировка
tests/                        автотесты (pytest)
```

Состояния отправки: `pending` → `sending` → `sent` | `failed` | `unknown`, а также `cancelled` и `skipped`. Все переходы записываются в таблицу `delivery_events`.

## Тесты

```
pip install -r requirements-dev.txt
pytest -q
```

Тесты проверяют: однократную отправку в каждый чат, защиту от двойного нажатия, повторного события и повторного запуска; атомарность резервирования; восстановление после «отключения питания»; запрет автоматического повтора при неизвестном результате; повтор с теми же `random_id`; FloodWait, отказы и блокировку аккаунта; паузу, продолжение и отмену; отказ параллельного запуска; сохранение выбора чатов; маскирование журнала; правила прав отправки и разбор ответа Telegram.

Настоящая отправка в Telegram автотестами не проверяется: для этого нужен реальный аккаунт. Перед первой реальной рассылкой проверьте работу на 1–2 своих тестовых группах.
